# Tools, data, and software connections

[Documentation home](../README.md)

SilexHub groups its product direction into three capability areas.

| Area | Purpose | What to inspect |
| --- | --- | --- |
| Tools | Transform, check, compare, or produce an artifact from a defined input | Supported task, input bounds, output format, and failure behavior |
| Data | Supply structured information, datasets, or knowledge assets | Source, coverage, version, update timing, and usage rights |
| Software connections | Perform an authorized action in another software workflow | Action scope, required grants, side effects, and result |

## Capabilities and delivery formats

A capability is the useful job. A file, structured result, workflow, or MCP interface is a delivery or access format. Choose the format that fits the next step; a downloadable artifact and a remotely operated service have different access and update requirements.

Each release must explain what is included, its limits, and the contract a caller can rely on. Product categories do not imply that every format or integration is already available.

## People and agents

People decide what to use and authorize access. Agents act within that scope. Permission and ownership checks belong in the service handling a request; a client configuration is not an authorization guarantee.

SilexHub's current model is a first-party offering. Third-party seller onboarding is not part of the current product.

See [current availability](../reference/availability.md) before attempting an integration.
