# Getting started with SilexHub

[Documentation home](README.md)

SilexHub is being built for practical tasks that need a tool, data, or an authorized software connection. Start with the result you need, then choose a capability and delivery method that fits the task.

## 1. Define the job

Write down the input you have, the result you need, and where that result goes next. For example, a business-information comparison needs records, comparison rules, and an output that makes differences easy to review. This is a workflow example, not a released SilexHub product.

## 2. Check what is available

Browse the [English or Chinese website](https://silexhub.com/en), read [articles](https://silexhub.com/en/articles) and [product guides](https://silexhub.com/en/docs), and explore the [read-only demo](https://silexhub.com/en/demo) without an account. Check [current availability](reference/availability.md) for account access, checkout and integrations.

Demo records are synthetic and do not run tasks or incur charges. Paid capabilities and runnable API/MCP integrations will be linked only when released and verified.

## 3. Choose an access method when released

A person may retrieve an artifact directly. An agent may use a documented API or MCP connection. The supported route depends on the capability and will be explained in its guide. There is no supported SilexHub installation command, public API endpoint, or MCP configuration to use today.

## 4. Review before using

For a released capability, check its inputs, output format, scope, permission requirements, usage rules, and error behavior. Use a small permitted example before building a larger workflow around it.

## Tell us what you need

[Submit a capability request](https://github.com/silexhub/silexhub/issues/new) with the task, a synthetic input, the desired output, and relevant constraints. Keep customer records and credentials out of public feedback.
